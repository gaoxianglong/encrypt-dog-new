## Why

执行页（ProgressPanel）每秒全量重建文件列表，暴露出两个用户可见的缺陷：一是在文件数量多出现滚动条时，用户把滚动条拉到任意位置后，下一次刷新视图会被强行拉回列表顶部，滚动条"瞄定"的位置看到的文件变成正在加密的文件（视口位置与滚动条脱钩）；二是执行完成瞬间，总耗时数字从处理期间的数值（如 60s）倒退几秒（如 57s），因为处理期间与完成态使用了两把起点不同的时钟。两个问题都破坏执行页的观察体验，且都是可稳定复现的确定性缺陷，应当修复。

## What Changes

- 执行页每次进度刷新重建行列表时，保留视口滚动位置：刷新前后用户停留在同一列表位置，不再被拉回顶部（方案 A：重建前保存 viewport 位置、重建后恢复，已用最小 Swing 实验验证有效）。
- 执行页总耗时统一采用 GUI 自己的时钟：处理期间与完成态显示同一口径（从用户点击开始操作到操作完成的完整耗时），完成时不再用 core 的 `timeConsuming` 覆盖，杜绝数值倒退。
- 附带：行尺寸未变化时跳过对行容器的冗余 `setBounds`/`setPreferredSize` 调用（实验证实这两个调用是触发视口位置重置的元凶，跳过本身即部分缓解）。

## Capabilities

### New Capabilities

（无）

### Modified Capabilities

- `swing-gui`: 执行表格页新增两条需求——进度刷新保持列表滚动位置；总耗时处理期间与完成态使用同一时钟口径。

## Impact

- 代码：`gui/interfaces/swing/ProgressPanel.java`（`refresh`/`rebuildRows`/`finish` 路径）；`beginMs`/`elapsedSeconds` 语义不变，仅 `finish()` 不再用 core 结果覆盖耗时显示。core 侧无改动。
- 行为：执行页滚动位置稳定、耗时数值单调不减；终端（console）视图不受影响（本次不碰 core 计时）。
- 依赖：无新增依赖。
- 验证：需要大量文件（列表出现滚动条）的真实执行场景 + 完成瞬间的耗时对照。
