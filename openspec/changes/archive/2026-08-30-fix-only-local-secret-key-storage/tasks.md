# Tasks: 修复 -o 模式秘钥存储链路

## 1. 密钥条目 v2 编解码（核心加密改造）

- [x] 1.1 新增密钥条目 v2 编解码工具：PBKDF2WithHmacSHA256（迭代数随条目存储，缺省 600_000，salt 16 字节随机）+ AES-256-GCM（nonce 12 字节随机，tag 16 字节），条目格式 `v2:<iter>:base64(salt16):base64(nonce12):base64(ct):base64(tag16)`；验证：单元测试加密→解码还原与原始随机密钥字节一致
- [x] 1.2 改造 `AbstractEncrypt.saveSecretKey` 以 v2 格式写入密钥条目，替换原「密文直接 UTF-8 String」路径；验证：`-o` 加密成功后 `~/.dog/DOG-SECRET-KEY.properties` 中条目以 `v2:` 开头且可被 1.1 的工具解析还原
- [x] 1.3 改造 `AbstractDecrypt.restoreKey` 为 v2 解析 + GCM 标签校验恢复随机密钥，不再经 UTF-8 往返；验证：同一设备用正确密码解密 `-o` 文件成功还原随机密钥并得到与原始一致的明文
- [x] 1.4 恢复失败 fail-loud 四类错误：密码错误（标签校验失败）/ 记录缺失（无条目）/ 条目损坏（非 v2 或解析失败，提示用原密码重新加密）/ 设备不匹配（沿用现有语义），`restoreKey` 不再静默返回；验证：错误密码时 AES/3DES/XOR 三种算法均报告密码错误且不产出明文文件，缺失/损坏条目分别给出对应提示

## 2. 并发与持久化安全

- [x] 2.1 密钥文件写入加跨进程锁：独立 `DOG-SECRET-KEY.properties.lock` 文件 + `FileChannel.lock()` 覆盖整个读-改-写周期，进程内保留 `synchronized`；验证：两个进程同时对多文件执行 `-o` 加密后，全部文件的条目均存在且各文件均可用各自条目解密
- [x] 2.2 写入改为同目录临时文件 + `Files.move(ATOMIC_MOVE, REPLACE_EXISTING)` 原子替换，临时文件以 600 权限创建，旧存储文件首次重写时同步收紧为 600；验证：写入后存储文件权限为仅属主可读写；模拟写入中途失败（如临时文件写入异常）后已存在的其它条目不受影响

## 3. fileId 随机化

- [x] 3.1 加密侧 fileId 生成改为 `UUID.randomUUID().getMostSignificantBits()`，文件头仍写入 8 字节，解密端读取逻辑不变；验证：`-o` 加解密全链路可用，文件头长度与布局不变，properties 条目键为新的随机 fileId

## 4. 性能与工程细节

- [x] 4.1 密钥派生每文件仅一次：派生结果缓存至任务级上下文（`EncryptContext`），`dataEncrypt`/`dataDecrypt` 各分块复用，不改变派生输入输出字节；验证：大文件（≥100MB）加密过程日志/埋点确认派生仅执行一次，且同一文件新旧实现的密文输出字节完全一致（回归对照）
- [x] 4.2 `createSecretkeyFile` 仅在加密路径执行，解密时密钥文件不存在直接走「记录缺失」错误；验证：无密钥文件时解密 `-o` 文件报记录缺失且不创建空文件
- [x] 4.3 硬件 ID 获取失败（命令无输出/返回 null）时给出可读错误信息，替代现有 NPE 路径；验证：模拟命令失败场景报出可操作的错误提示
