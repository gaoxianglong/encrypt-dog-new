# 菜单栏常驻托盘（双进程）

## Why

用户希望加解密程序首次运行后在 macOS 菜单栏出现 logo 小图标，GUI 窗口关闭后图标仍在，并可通过图标重新唤醒 GUI，图标提供独立的退出按钮。选择**双进程架构**的核心原因：GUI 渲染消耗 CPU——星空粒子背景以 16ms 帧率持续动画（`ParticlePanel` FRAME_DELAY_MS=16）、执行页马赛克脉冲等 60fps 级渲染在窗口可见期间持续烧 CPU。若采用单进程常驻（关窗仅隐藏），渲染进程与全部动画定时器永不退出；双进程将"渲染重"的 GUI 与"零渲染"的托盘守护彻底隔离：GUI 退出即释放全部渲染开销，常驻守护仅挂一枚静态图标（无窗口、无定时器、无动画），CPU/内存常驻开销趋近于零。

## What Changes

- 新增**托盘守护进程**：同一份 jar 的 `--tray` 运行模式，以 `java -Xmx64m -jar dog.jar --tray` 形式由 GUI 启动时自动拉起（用户无感），仅挂载菜单栏图标（logo.png，22pt + 2x 变体），不创建窗口、不运行任何渲染动画。
- **首次 GUI 启动**（`--gui`）时确保守护在跑（探测本地端口，缺则拉起）；守护已在则不重复拉起。**终端模式（不带 `--gui`）完全不触碰托盘**，行为不变。
- 托盘菜单两项：`Open Encrypt Dog`（唤醒/拉起 GUI）、`Quit`（独立的退出按钮）。
- **单例唤醒**：托盘 Open 或二次 `--gui` 启动时，若 GUI 已在运行则把已有窗口带到前台，不重复开窗；GUI 未运行时托盘 Open 拉起新 GUI 进程。
- **退出语义**：GUI 点 ✕ 仅退出 GUI 进程（EXIT_ON_CLOSE 语义不变），菜单栏图标保留；托盘 Quit 时若 GUI 仍在运行则先通知其关闭，随后图标消失、守护进程退出（全退干净）。两个默认均按用户确认执行。
- **自愈**：守护进程被外部杀掉后，下次 GUI 启动自动重新拉起。
- **优雅降级**：托盘端口被陌生程序占用（握手失败）时，GUI 正常使用只是无托盘，不崩溃。

## Capabilities

### New Capabilities

- `menu-bar-tray`: macOS 菜单栏常驻托盘能力——守护进程生命周期、图标与菜单、单例唤醒、退出语义、自愈与端口冲突降级。

### Modified Capabilities

- `swing-gui`: 「启动参数路由」需求扩展：新增 `--tray` 参数路由到托盘守护模式（无窗口）；`--gui` 启动流程增加"确保托盘守护运行"步骤；终端模式路径不变。

## Impact

- 受影响代码：`Starter.java`（`--tray` 路由）、新增托盘守护入口类（SystemTray/TrayIcon/PopupMenu）、新增本地 socket 通信小工具（守护端口 + GUI 单例端口，仅 localhost、魔数握手）、`EncryptDogGui.launch` 前置守护确保与 GUI 单例监听。
- 复用既有资源：`logo.png`（`LogoUtil` 等比缩放出 22px/44px 双档）；无新依赖。
- 终端模式零影响；GUI 模式可见行为变化（✕ 关闭后图标仍在、二次启动带前台）。
